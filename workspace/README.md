# Workspace

`workspace/` is Francis's live local runtime substrate.

It is not source code and it is not meant to be a durable git history of:

* receipts
* ledgers
* inbox messages
* incidents
* telemetry streams
* queue state
* takeover exports
* Forge staging packs
* Forge reports
* temporary chain and tool runtime artifacts

Those files are generated by Francis while the system runs. They are allowed to change constantly and should stay local to the machine unless they are intentionally exported or promoted elsewhere.

Some runtime ledgers are also normalized in place during hardening work. Queue rows may move into states such as `superseded`, observer-managed incidents may be refreshed or resolved in place, pathological observer baseline thresholds may be rewritten before they can keep false anomalies open, stale quarantine-generated security incidents may be resolved by governed repair, stale synthetic inbox rows may be archived when Francis repairs legacy test residue, stale `source=pytest` telemetry rows may be pruned when they only reflect verification history, inbox messages may be archived or superseded when Francis replaces a managed system briefing, and stale synthetic missions may be cancelled by governed repair. Those lifecycle states exist so active pressure reflects current truth instead of raw append volume.

Shared-workspace integration tests also need to stay serial when they touch the live runtime substrate. Parallel pytest sessions against `workspace/` can invalidate results on Windows by locking files such as `workspace/journals/fs.jsonl` while another session is still cleaning up.

Git tracks only this policy file and the local ignore rules in [`.gitignore`](./.gitignore).

If a runtime artifact needs to become a product asset, test fixture, or canonical example, promote it into a real repo surface such as:

* `docs/`
* `tests/fixtures/`
* `packages/`
* `services/`

Do not recommit raw `workspace/` churn by default.
